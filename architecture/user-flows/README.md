# User Flows

권한별 사용자 플로우 문서

## 📖 개요

CDE 시스템의 3가지 사용자 권한별 시스템 사용 흐름을 정의합니다.

---

## 🔐 권한 체계

### Master
- **역할**: 시스템 최고 관리자
- **특징**: 고객사 당 1개 계정
- **주요 권한**:
  - ✅ 모든 메뉴 접근
  - ✅ 사용자 생성/수정/삭제
  - ✅ Management 메뉴 독점
  - ✅ 프로젝트 전체 관리
  - ✅ Usage 통계 조회

### Manager
- **역할**: 폴리시 결재 승인자
- **특징**: 여러 명 가능
- **주요 권한**:
  - ✅ 폴리시 승인/거절
  - ✅ 승인 후 관리 (Revoke/Terminate)
  - ✅ 사후 승인 (롤백)
  - ✅ 프로젝트 조회 (Read/Update)
  - ❌ Management 메뉴 접근 불가

### User
- **역할**: 프로젝트 관리자
- **특징**: 여러 명 가능
- **주요 권한**:
  - ✅ 프로젝트 전체 관리 (CRUD)
  - ✅ 폴리시 승인 요청
  - ✅ 테스트 & 분석
  - ❌ 승인/거절 권한 없음
  - ❌ Management 메뉴 접근 불가

## 📄 User Flow 문서

### [01. Master 사용자 플로우](./01-master-flow.md)

**주요 프로세스:**
1. **로그인 → 대시보드**
2. **메뉴 선택 (3가지 주요 분기)**:
   - 프로젝트 관리
   - 사용자 관리 (Master 전용)
   - Management (Master 전용)
3. **폴리시 결재 프로세스**:
   - 생성 → 승인 요청 → Manager 검토 → 승인/거절 → 배포
4. **모니터링 및 롤백**

**Master 전용 기능:**
- 사용자 생성 (난수 비밀번호 Email 발송)
- 권한 할당 (Manager/User)
- 비밀번호 초기화
- 트랜잭션 통계
- 월간/연간 사용량

---

### [02. Manager 사용자 플로우](./02-manager-flow.md)

**주요 프로세스:**
1. **로그인 → 알림 확인**
2. **폴리시 검토**:
   - Requested 알림 수신
   - 상세 내용 확인
3. **결재 결정**:
   - 승인 (Approved) → User 알림
   - 거절 (Rejected) → User 알림
4. **승인 후 관리**:
   - 배포 (Active/Scheduled)
   - 승인 취소 (Revoke)
   - 운영 중단 (Terminate)
   - 일정 변경 (Reschedule)
5. **사후 승인** (롤백 시)

**Manager 알림:**
- 📩 Requested: User 승인 요청
- 📩 Withdrawn: User 결재 취소
- 📩 Rollback: 롤백 사후 승인 필요

**Manager 권한:**
- ✅ 승인/거절 코멘트 작성 필수
- ✅ 배포 옵션 선택
- ✅ 운영 중단 권한
- ❌ 프로젝트 생성/삭제 불가

---

### [03. User 사용자 플로우](./03-user-flow.md)

**주요 프로세스:**
1. **첫 로그인**:
   - 난수 비밀번호로 로그인
   - 비밀번호 변경 필수
2. **프로젝트 관리**:
   - 프로젝트 선택/생성
   - 5가지 구성 요소 생성
3. **구성 요소 생성**:
   - **Parameter**: 원본변수 (6가지 입력) + 파생변수
   - **Segment**: 1-3개 파라미터 매트릭스
   - **Scoring**: Score Card / AI Model
   - **Rule**: Condition Group + Decision
   - **Policy**: Rules/Matrix 조합
4. **폴리시 승인 프로세스**:
   - Pending → 승인 요청 → Requested
   - 결재 취소 가능 (Manager 승인 전)
   - 결과 대기 (Approved/Rejected/Revoked)
5. **테스트 & 분석**:
   - Policy Test (챔피언/챌린저)
   - Simulation (과거 데이터)
   - Active History (롤백)

**User 알림:**
- 📩 Approved: 승인 완료
- 📩 Rejected: 거절 (수정 필요)
- 📩 Revoked: 승인 취소 (수정 필요)
- 📩 Scheduled: 운영 예약
- 📩 Canceled: 운영 취소

**User 제한 사항:**
- ❌ 승인/거절 권한 없음
- ❌ 사용자 생성/삭제 불가
- ❌ Management 메뉴 접근 불가
- ❌ Manager 승인 후 결재 취소 불가

## 🔄 공통 프로세스

### 로그인
- ID/PW 입력
- 세션 생성 (30분 유효)
- 동시 접속 불가
- 로그인 실패 5회 시 30분 잠금

### 비밀번호 정책
- **최소 길이**: 영문/숫자/기호 3가지 사용 8자 이상
- **최대 사용 기간**: 6개월
- **최소 사용 기간**: 1일
- **복잡성**: 공백 불가, 동일 문자 3개 이상 반복 불가, 숫자 순차 3개 이상 불가, ID 포함 불가
- **최신 PW 기억**: 1개 (최근 비밀번호 사용 불가)

### 알림
- 14일 보관
- 자동 삭제
- 알림 유형에 따라 Manager/User 수신

## 🎯 주요 시나리오

### 시나리오 1: 신규 폴리시 배포
1. **User**: 프로젝트 생성 → 구성 요소 생성 → 폴리시 완성
2. **User**: 승인 요청 (Manager 선택)
3. **Manager**: 알림 수신 → 폴리시 검토
4. **Manager**: 승인 → 배포 옵션 선택 (Active)
5. **System**: 버저닝 및 Active History 기록
6. **User**: 승인 알림 수신

### 시나리오 2: 폴리시 거절 및 재요청
1. **User**: 승인 요청
2. **Manager**: 거절 (코멘트: 수정 필요)
3. **User**: 거절 알림 수신
4. **User**: 폴리시 수정
5. **User**: 재승인 요청
6. **Manager**: 승인 → 배포

### 시나리오 3: 롤백 및 사후 승인
1. **User**: Active History에서 과거 폴리시 선택
2. **User**: 롤백 실행 (코멘트 작성)
3. **System**: 즉시 배포 (승인 전)
4. **Manager**: 로그인 시 사후 승인 모달 강제 출력
5. **Manager**: 코멘트 작성 → 승인
6. **User**: 사후 승인 완료 알림 수신

### 시나리오 4: Master의 사용자 관리
1. **Master**: Management 메뉴 접근
2. **Master**: 사용자 생성 (ID/Name/Email/Role)
3. **System**: 난수 비밀번호 생성 → Email 발송
4. **신규 User**: Email 확인 → 첫 로그인
5. **System**: 비밀번호 변경 모달 강제 출력
6. **신규 User**: 새 비밀번호 설정 → 서비스 접근
